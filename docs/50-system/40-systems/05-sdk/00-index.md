# Client SDKs (SDK) — Overview

## 1. Purpose

The SDKs are the only way clients talk to UBOS (AR-003). Each SDK implements UBTP (CTR-003),
authentication flows, idempotent retries, snapshot-consistent paging, subscriptions with
resumable cursors, uploads, and typed access generated by Forge. WSP, STU, the Box shell,
AGT, BRG, NTY and third-party applications all use an SDK.

| SDK | Package | Phase |
|---|---|---|
| Rust | `ubos-sdk` crate | PH-1b |
| TypeScript (browser and Node.js) | `@ubos/sdk` | PH-1b |
| Python | `ubos-sdk` on PyPI | PH-3 |
| Java/Kotlin, .NET | generated from the protocol schemas, community-maintained with conformance | PH-4 |

## 2. Responsibilities and non-responsibilities

| Responsible for | Not responsible for |
|---|---|
| protocol, sessions, reconnection, retries | business rules (DVM) |
| typed models and queries (generated) | UI rendering (WSP) |
| client caches keyed by version | offline authoritative storage (Box NOD) |
| upload and download helpers | sync protocol internals (NOD, DVM) |
| error mapping to typed errors | error semantics (standard error registry) |
