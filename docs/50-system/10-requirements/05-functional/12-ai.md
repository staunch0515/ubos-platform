# Functional Requirements — AI

Governing principle (IMP-10, principle P3): AI never bypasses validation, drafts, approval
or authorization. Agents are principals that work in their own branches.

## CAP-AI-01 — Model gateway

### FR-AI-011 — Provider-neutral routing
- **Statement:** All model calls from any system MUST go through the model gateway. The gateway routes to configured providers or self-hosted models by route policy (task type, data classification, region, cost ceiling) and exposes one internal interface.
- **Rationale:** Control, portability and compliance of AI usage.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-SecurityOfficer, PER-TenantAdministrator
- **Acceptance:**
  1. Given two providers and a route "personal data → self-hosted only", when a prompt with personal data is sent, then it is routed to the self-hosted model.
- **Verification:** CONF, SEC
- **Origin:** L40:SPEC-27

### FR-AI-012 — Metering and cost attribution
- **Statement:** The gateway MUST meter tokens, requests and cost per call, and MUST attribute them to tenant, VAE, principal (human or agent), asset and process.
- **Rationale:** Budgets and billing (CAP-BILL-01).
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-AgentSupervisor, PER-TenantAdministrator
- **Acceptance:**
  1. Given 100 calls, when the metering is summed, then it equals the provider-reported usage within rounding.
- **Verification:** CONF
- **Origin:** NEW

### FR-AI-013 — Classification enforcement and redaction
- **Statement:** Before a prompt leaves the platform, the gateway MUST enforce the route's allowed classifications, redact or tokenise fields as configured, and block calls that would send disallowed data.
- **Rationale:** Privacy and confidentiality (DEC-003).
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-ComplianceOfficer
- **Acceptance:**
  1. Given a route that allows `internal` only, when a prompt contains a `confidential` field, then the call is blocked with `AI.CLASSIFICATION_BLOCKED`.
- **Verification:** SEC, CONF
- **Origin:** NEW

### FR-AI-014 — Recording
- **Statement:** The gateway MUST record every call (route, model and version, prompt template version, inputs after redaction, output, tokens, latency) in the execution journal of the calling process, with retention by policy.
- **Rationale:** Audit and replay (FR-LOGIC-072).
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-InternalAuditor
- **Acceptance:**
  1. Given an agent run, when audited, then every model call is listed with versions.
- **Verification:** CONF
- **Origin:** L40:SPEC-27

### FR-AI-015 — Region and provider allow-lists
- **Statement:** Tenants MUST be able to restrict providers and processing regions. The gateway MUST reject routes that violate the restrictions or residency (FR-TEN-073).
- **Rationale:** Residency and vendor policy.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, CTL
- **Personas:** PER-ComplianceOfficer
- **Acceptance:**
  1. Given a US-only tenant, when an EU-hosted route is configured, then it is rejected.
- **Verification:** CONF
- **Origin:** NEW

### FR-AI-016 — Resilience and limits
- **Statement:** The gateway MUST apply rate limits per tenant and principal, and fallback routes on provider failure only when the fallback satisfies the same policy.
- **Rationale:** Availability without policy drift.
- **Priority:** Should · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-PlatformOperator
- **Acceptance:**
  1. Given a provider outage, when calls continue, then they use a compliant fallback or fail with `AI.PROVIDER_UNAVAILABLE`.
- **Verification:** FAULT
- **Origin:** NEW

## CAP-AI-02 — Agent identity and budget

### FR-AI-021 — Agents are principals with scope and budget
- **Statement:** Every agent MUST be a principal of kind `agent` with:
  - roles and a data scope (classes, VAEs, branches);
  - budgets for tokens, cost, commits, actions and wall time per period;
  - a responsible supervisor.

  Exceeding a budget MUST stop further consumption with `AI.BUDGET_EXHAUSTED`.
- **Rationale:** SCN-302.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, DVM
- **Personas:** PER-AgentSupervisor, PER-SecurityOfficer
- **Acceptance:**
  1. Given SCN-302 step 2, when the budget is exhausted, then the run ends with a partial change set.
- **Verification:** SCN, CONF
- **Origin:** IMP-10

### FR-AI-022 — Kill switch
- **Statement:** Supervisors and security officers MUST be able to stop an agent or all agents of a VAE immediately. In-flight tool calls MUST be cancelled within the NR-PERF bound, and the agent's branches frozen.
- **Rationale:** Instant containment.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-AgentSupervisor
- **Acceptance:**
  1. Given SCN-302 step 3, when "stop" is pressed, then cancellation completes within 2 seconds.
- **Verification:** SCN, FAULT
- **Origin:** IMP-10

### FR-AI-023 — Agent definitions are governed objects
- **Statement:** An agent's configuration (model route, prompt templates, tool set, knowledge scope, schedule, budgets) MUST be a versioned Definition object under `change_set` policy.
- **Rationale:** Agent behaviour changes are reviewed changes.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, DVM
- **Personas:** PER-AgentSupervisor
- **Acceptance:**
  1. Given a prompt change, when proposed, then it requires approval, and the run records show the version used.
- **Verification:** CONF
- **Origin:** IMP-10

### FR-AI-024 — Triggers for agents
- **Statement:** Agents MUST be startable by schedule, by event subscription, by user request or by another process, with lineage recorded.
- **Rationale:** Agents fit the event and job model.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, NOD
- **Personas:** PER-AgentSupervisor
- **Acceptance:**
  1. Given a 19:00 schedule, when it fires, then an agent run starts with the schedule as its trigger.
- **Verification:** CONF
- **Origin:** NEW

### FR-AI-025 — No self-merge
- **Statement:** An agent principal MUST NOT approve or merge its own change sets. Merging requires a human approver or an explicitly configured policy approver that is not the same agent.
- **Rationale:** Separation of duties for AI.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, DVM
- **Personas:** PER-SecurityOfficer
- **Acceptance:**
  1. Given SCN-302 A1, when attempted, then it is denied.
- **Verification:** SEC
- **Origin:** IMP-10

## CAP-AI-03 — Agent branches

### FR-AI-031 — One branch per agent run
- **Statement:** Each agent run that changes state MUST work on its own branch of kind `agent`, named `agent/<agent>/<run>`. Writes outside that branch MUST be denied, except appends to ledgers explicitly granted for direct agent posting by policy.
- **Rationale:** Isolation of AI work (IMP-10).
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, DVM
- **Personas:** PER-AgentSupervisor, PER-AiAgent
- **Acceptance:**
  1. Given an agent run, when it writes, then the commits appear only on its branch.
- **Verification:** CONF, SEC
- **Origin:** IMP-10

### FR-AI-032 — Simulation before submission
- **Statement:** Before submitting a change set, the agent run MUST execute validation and the merge preview. The results MUST be attached to the change set, and submission MUST be refused if validation fails.
- **Rationale:** Humans review only valid proposals.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, DVM
- **Personas:** PER-AgentSupervisor
- **Acceptance:**
  1. Given an invalid proposal, when submitted, then it is rejected with structured feedback (SCN-307).
- **Verification:** CONF, SCN
- **Origin:** IMP-10

### FR-AI-033 — Summaries and confidence
- **Statement:** Agent change sets MUST include a natural-language summary, per-item rationale and a confidence value, and MUST cite the evidence objects used.
- **Rationale:** Efficient review (SCN-301).
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-AgentSupervisor
- **Acceptance:**
  1. Given a change set, when reviewed, then every item has a rationale and cited evidence.
- **Verification:** SCN, USE
- **Origin:** IMP-10

### FR-AI-034 — Structured feedback loop
- **Statement:** Rejections and partial acceptances MUST produce structured feedback (items, reasons, reviewer) stored for the agent's evaluation and, where configured, provided to subsequent runs.
- **Rationale:** Agents improve from review.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-AgentSupervisor
- **Acceptance:**
  1. Given 2 rejected items, when the next run starts, then its context includes the feedback records.
- **Verification:** CONF
- **Origin:** IMP-10

### FR-AI-035 — Revert of merged agent work
- **Statement:** Merged agent changes MUST be revertible per item, per change set and per run (CAP-VER-07).
- **Rationale:** 100% revertibility goal (G4).
- **Priority:** Must · **Phase:** PH-3 · **Systems:** DVM
- **Personas:** PER-AgentSupervisor
- **Acceptance:**
  1. Given a merged run, when reverted, then all its effects are compensated, and history shows both.
- **Verification:** SCN
- **Origin:** IMP-10

## CAP-AI-04 — Tool exposure

### FR-AI-041 — Ports and queries as typed tools
- **Statement:** Every port and saved query MUST be available as a typed tool with a JSON Schema for its parameters and results, a description from the model, and error descriptions.
- **Rationale:** The model is the agent's world model (IMP-10).
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, DVM
- **Personas:** PER-AiAgent
- **Acceptance:**
  1. Given the `DealingOrder.submit` port, when the tool list is fetched, then a tool with its parameter schema and description exists.
- **Verification:** CONF
- **Origin:** IMP-10

### FR-AI-042 — MCP server
- **Statement:** Agent Hub MUST expose the tools, resources (object reads and knowledge) and prompts through the Model Context Protocol for authorised external clients (FR-IAM-104).
- **Rationale:** Interoperability with any AI client (IMP-12).
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-AiAgent, PER-BusinessUser
- **Acceptance:**
  1. Given a compliant MCP client, when connected with a delegation, then it can list and call the permitted tools.
- **Verification:** CONF, SCN
- **Origin:** IMP-10, IMP-12

### FR-AI-043 — Permission-filtered tool sets
- **Statement:** The tool set presented to an agent or client MUST contain only tools that its principal may invoke in its scope.
- **Rationale:** Least privilege and smaller prompts.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-SecurityOfficer
- **Acceptance:**
  1. Given an agent scoped to reconciliation, when listing tools, then no investor-account tools appear.
- **Verification:** SEC
- **Origin:** IMP-10

### FR-AI-044 — Tool call recording
- **Statement:** Each tool call MUST be recorded with parameters, results (masked), principal chain and duration, linked to the agent run.
- **Rationale:** Audit of AI actions.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-InternalAuditor
- **Acceptance:**
  1. Given a run with 40 tool calls, when audited, then 40 records exist.
- **Verification:** CONF
- **Origin:** NEW

### FR-AI-045 — Preview tools
- **Statement:** For each command tool, a preview variant MUST exist that validates and simulates without writing.
- **Rationale:** Agents check before acting.
- **Priority:** Should · **Phase:** PH-3 · **Systems:** AGT, DVM
- **Personas:** PER-AiAgent
- **Acceptance:**
  1. Given the preview of `submit`, when called with invalid input, then the violations are returned, and no change occurs.
- **Verification:** CONF
- **Origin:** NEW

## CAP-AI-05 — BPU knowledge

### FR-AI-051 — Knowledge objects on classes
- **Statement:** Classes MUST be able to attach knowledge objects: explanations, procedures, policies, examples, FAQs and reference documents. They are versioned and bitemporal like other Definition objects.
- **Rationale:** The BPU "embedded knowledge base" (EXT-BPU).
- **Priority:** Must · **Phase:** PH-3 · **Systems:** DVM, AGT
- **Personas:** PER-BusinessArchitect, PER-AiAgent
- **Acceptance:**
  1. Given a procedure attached to `DealingOrder`, when an agent works on an order, then the procedure is retrievable in context.
- **Verification:** CONF
- **Origin:** EXT-BPU

### FR-AI-052 — Retrieval index per class
- **Statement:** Knowledge and declared record content MUST be retrievable by text and vector search (CAP-QRY-03), scoped to the class chain and the caller's permissions.
- **Rationale:** Grounded answers.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, DVM
- **Personas:** PER-AiAgent, PER-BusinessUser
- **Acceptance:**
  1. Given a question about cut-off rules, when asked, then the cut-off procedure ranks first.
- **Verification:** CONF
- **Origin:** IMP-10

### FR-AI-053 — Temporal knowledge
- **Statement:** Retrieval MUST honour `asof`, so that answers about past cases use the knowledge effective at that time.
- **Rationale:** "Which policy applied then?"
- **Priority:** Should · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-ComplianceOfficer
- **Acceptance:**
  1. Given a policy changed in June, when asked about a March case, then the March policy is cited.
- **Verification:** CONF
- **Origin:** IMP-02

### FR-AI-054 — Citations
- **Statement:** AI answers and proposals that use knowledge or records MUST cite them by URI and version.
- **Rationale:** Verifiable AI output.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-BusinessUser, PER-AgentSupervisor
- **Acceptance:**
  1. Given a copilot answer, when displayed, then each claim links to its sources.
- **Verification:** SCN, INSP
- **Origin:** NEW

## CAP-AI-06 — Copilot

### FR-AI-061 — In-context assistance
- **Statement:** Workspace MUST provide a copilot that knows the current page context (record, view, temporal context) and can answer, explain and draft within the user's permissions.
- **Rationale:** SCN-303.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, WSP
- **Personas:** PER-BusinessUser, PER-ContractManager
- **Acceptance:**
  1. Given an open agreement, when "what are my obligations next month?" is asked, then the answer lists the obligations with citations.
- **Verification:** SCN, USE
- **Origin:** L40:SPEC-27

### FR-AI-062 — Proposals, never silent commits
- **Statement:** Copilot changes MUST be proposals (drafts or change sets) that the user reviews and submits. The copilot MUST NOT commit on the user's behalf without an explicit confirmation step.
- **Rationale:** Principle P3.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, WSP
- **Personas:** PER-BusinessUser
- **Acceptance:**
  1. Given SCN-303, when the copilot proposes an amendment, then nothing changes until the user submits.
- **Verification:** SCN
- **Origin:** IMP-10

### FR-AI-063 — Clarification over guessing
- **Statement:** When a request is ambiguous with respect to dates, amounts, targets or scope, the copilot MUST ask a clarification question instead of assuming.
- **Rationale:** SCN-303 A1.
- **Priority:** Should · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-BusinessUser
- **Acceptance:**
  1. Given the evaluation set of ambiguous requests, when run, then at least 90% produce clarification questions.
- **Verification:** SCN, USE
- **Origin:** NEW

### FR-AI-064 — Explain records, rules and lineage
- **Statement:** The copilot MUST explain effective rules, validation failures and value lineage using the platform's explanation and lineage APIs, not model speculation.
- **Rationale:** Trustworthy explanations.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-BusinessUser, PER-FundAccountant
- **Acceptance:**
  1. Given "why was this rejected?", when asked, then the answer reproduces the explanation object's content with citations.
- **Verification:** SCN
- **Origin:** NEW

## CAP-AI-07 — AI builder

### FR-AI-071 — Generate Buk drafts from requirements
- **Statement:** The builder MUST generate Buk drafts (classes extending the ontology, lifecycles, L1 rules, views, knowledge and scenarios) from natural-language requirements, as a change set on a feature branch.
- **Rationale:** SCN-304.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, STU, FRG
- **Personas:** PER-BusinessArchitect
- **Acceptance:**
  1. Given the "Asset Loan" note, when built, then a draft Buk exists that passes Forge checks after at most 3 iterations.
- **Verification:** SCN
- **Origin:** L40:SPEC-27

### FR-AI-072 — Iterate on Forge findings
- **Statement:** The builder MUST run Forge checks and address findings automatically, within its budget, before presenting the draft.
- **Rationale:** Reviewers see checked drafts.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, FRG
- **Personas:** PER-BusinessArchitect
- **Acceptance:**
  1. Given 2 findings, when iterated, then the presented draft has 0 blocking findings or explains the remaining ones.
- **Verification:** SCN
- **Origin:** NEW

### FR-AI-073 — Provenance of generated content
- **Statement:** Generated objects MUST carry provenance (agent, model version, prompt version, generation time), and human edits MUST be attributed separately.
- **Rationale:** Accountability for AI-generated business logic.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, DVM
- **Personas:** PER-InternalAuditor
- **Acceptance:**
  1. Given an edited generated rule, when inspected, then both the generation and the edit are attributed.
- **Verification:** CONF
- **Origin:** NEW

### FR-AI-074 — Ontology-first generation
- **Statement:** The builder MUST prefer extending ontology and installed classes over creating parallel classes, and MUST justify any new root-level business class.
- **Rationale:** SCN-304 A1.
- **Priority:** Should · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-BusinessArchitect
- **Acceptance:**
  1. Given a requirement mentioning customers, when built, then the class extends `Organisation` or `Person`.
- **Verification:** SCN
- **Origin:** NEW

## CAP-AI-08 — Evaluation and monitoring

### FR-AI-081 — Evaluation suites
- **Statement:** Agents MUST have evaluation suites built from scenarios and from historical reviewed change sets, run on every agent-definition change, with results attached to the change set.
- **Rationale:** Regression control for AI behaviour.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-AgentSupervisor
- **Acceptance:**
  1. Given a prompt change, when evaluated, then the acceptance-rate delta against the baseline is reported.
- **Verification:** CONF, SCN
- **Origin:** NEW

### FR-AI-082 — Quality metrics
- **Statement:** Agent Hub MUST track per agent: change-set acceptance rate, item acceptance rate, validation-failure rate, revert rate, scope-violation count and time to review.
- **Rationale:** G4 measurement.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-AgentSupervisor
- **Acceptance:**
  1. Given a month of runs, when the dashboard is shown, then each metric is computed from records.
- **Verification:** CONF
- **Origin:** NEW

### FR-AI-083 — Cost monitoring
- **Statement:** Agent Hub MUST alert on cost anomalies and on budgets crossing configurable thresholds.
- **Rationale:** Cost control.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-AgentSupervisor, PER-TenantAdministrator
- **Acceptance:**
  1. Given an 80% threshold, when crossed, then the supervisor is notified.
- **Verification:** CONF
- **Origin:** NEW

### FR-AI-084 — Version comparison
- **Statement:** Agent Hub SHOULD compare model or prompt versions on the same evaluation set and report differences in quality and cost.
- **Rationale:** Informed upgrades.
- **Priority:** Should · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-AgentSupervisor
- **Acceptance:**
  1. Given two model versions, when compared, then a side-by-side report is produced.
- **Verification:** CONF
- **Origin:** NEW

## CAP-AI-09 — AI inside logic

### FR-AI-091 — The `ask.model` instruction
- **Statement:** Logic MUST be able to call models only through `ask.model`, with a declared output schema. Outputs that do not validate against the schema MUST raise `AI.OUTPUT_INVALID`.
- **Rationale:** Structured, safe AI inside processes.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** DVM, AGT
- **Personas:** PER-LogicDeveloper
- **Acceptance:**
  1. Given an output schema `{category: enum}`, when the model returns free text, then the instruction fails.
- **Verification:** CONF
- **Origin:** L40:SPEC-27

### FR-AI-092 — Recorded for replay
- **Statement:** `ask.model` responses MUST be journaled, and replay MUST use the recorded response.
- **Rationale:** Determinism (FR-LOGIC-071).
- **Priority:** Must · **Phase:** PH-3 · **Systems:** DVM
- **Personas:** PER-InternalAuditor
- **Acceptance:**
  1. Given a replay, when `ask.model` is reached, then no model call is made, and the recorded output is used.
- **Verification:** CONF
- **Origin:** L40:SPEC-17

### FR-AI-093 — Profile limits for AI calls
- **Statement:** Execution profiles MUST limit the number, tokens and cost of `ask.model` calls per execution.
- **Rationale:** Cost containment.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** DVM
- **Personas:** PER-PlatformOperator
- **Acceptance:**
  1. Given a limit of 3 calls, when a fourth is made, then it fails with `LOGIC.LIMIT_EXCEEDED`.
- **Verification:** CONF
- **Origin:** NEW

### FR-AI-094 — AI outputs never bypass validation
- **Statement:** Values derived from model outputs MUST pass the same validation, decisions and approvals as any other input before commit.
- **Rationale:** L40 hard rule 10.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** DVM
- **Personas:** PER-SecurityOfficer
- **Acceptance:**
  1. Given a model-suggested value violating a constraint, when committed, then the commit fails.
- **Verification:** CONF
- **Origin:** L40:SPEC-27

## CAP-AI-10 — Governed evolution

### FR-AI-101 — Evolution analysers
- **Statement:** Classes MAY attach evolution analysers (agents) that monitor validation failures, overrides, manual corrections and exceptions, and detect recurring patterns.
- **Rationale:** "Self-evolving" BPUs (EXT-BPU), made safe.
- **Priority:** Should · **Phase:** PH-3 · **Systems:** AGT, DVM
- **Personas:** PER-BusinessArchitect
- **Acceptance:**
  1. Given SCN-306, when the analyser runs, then the pattern is detected.
- **Verification:** SCN
- **Origin:** EXT-BPU

### FR-AI-102 — Proposals on evolution branches
- **Statement:** Evolution proposals MUST be change sets on `evolution` branches, with evidence (pattern statistics), simulation results and tests.
- **Rationale:** Evidence-based change.
- **Priority:** Must · **Phase:** PH-3 · **Systems:** AGT, DVM
- **Personas:** PER-BusinessAnalyst
- **Acceptance:**
  1. Given SCN-306 step 2, when the proposal is opened, then the simulation over 120 cases is attached.
- **Verification:** SCN
- **Origin:** EXT-BPU

### FR-AI-103 — Only authorised merge
- **Statement:** A class, rule or view MUST NOT change as a result of evolution except through a merge approved by an authorised non-agent principal.
- **Rationale:** "BPUs propose; people decide" (UBS-META-06 §4).
- **Priority:** Must · **Phase:** PH-3 · **Systems:** DVM
- **Personas:** PER-BusinessArchitect
- **Acceptance:**
  1. Given an evolution proposal, when an agent attempts to merge it, then it is denied.
- **Verification:** SEC
- **Origin:** EXT-BPU

### FR-AI-104 — Suppression of rejected proposals
- **Statement:** Rejected proposals MUST be recorded with reasons, and equivalent proposals MUST be suppressed for a configurable period unless the evidence changes materially.
- **Rationale:** Avoid proposal fatigue.
- **Priority:** Should · **Phase:** PH-3 · **Systems:** AGT
- **Personas:** PER-BusinessAnalyst
- **Acceptance:**
  1. Given SCN-306 A1, when the analyser runs again within the period, then no duplicate proposal appears.
- **Verification:** SCN
- **Origin:** NEW
