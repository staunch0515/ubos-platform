# Glossary — M to Z

### GL-Masking — Masking
- **Definition:** Replacing or hiding field values in any output according to policy (hide, partial or hash).
- **Not to be confused with:** GL-CryptoShredding.
- **Visible to:** builder
- **Defined normatively in:** FR-IAM-061

### GL-Mcp — MCP (Model Context Protocol)
- **Definition:** The open protocol through which Agent Hub exposes tools, resources and prompts to AI clients.
- **Not to be confused with:** GL-Ubtp.
- **Visible to:** platform only
- **Defined normatively in:** FR-AI-042

### GL-Merge — Merge
- **Definition:** Combining the changes of a source branch into a target branch by three-way merge for Definition state and by append for Ledger state, producing one merge commit.
- **Not to be confused with:** replication by sync (CAP-SYNC-01).
- **Visible to:** platform only (business users see "publish")
- **Defined normatively in:** FR-VER-051

### GL-MergeBase — Merge Base
- **Definition:** The best common ancestor state used for three-way merge.
- **Not to be confused with:** a parent commit.
- **Visible to:** platform only
- **Defined normatively in:** FR-VER-051

### GL-MerkleRoot — Merkle Root
- **Definition:** The hash that commits to the complete state of a branch (or a tenant) at a commit, independent of history.
- **Not to be confused with:** a commit ID.
- **Visible to:** platform only
- **Defined normatively in:** FR-PROOF-031

### GL-Metering — Metering
- **Definition:** Measuring the resources consumed by executions and services, attributed to tenant, principal, asset and process.
- **Not to be confused with:** billing.
- **Visible to:** builder
- **Defined normatively in:** FR-LOGIC-063

### GL-ModelGateway — Model Gateway
- **Definition:** The single, governed path to AI models, with routing, redaction, metering and recording.
- **Not to be confused with:** GL-Gateway (`sys`).
- **Visible to:** builder
- **Defined normatively in:** FR-AI-011

### GL-NetworkFallback — Network Fallback
- **Definition:** The resolution order cache → local store → parent lookup → remote fetch for inherited items across nodes.
- **Not to be confused with:** a retry.
- **Visible to:** platform only
- **Defined normatively in:** FR-SYNC-062

### GL-Object — Object
- **Definition:** A versioned DVM item of any class, identified by UUID and locator.
- **Not to be confused with:** GL-Bpu (the business-level concept).
- **Visible to:** platform only (business users see "record")
- **Defined normatively in:** FR-MODEL-014

### GL-ObjectVersion — Object Version
- **Definition:** One immutable, content-addressed state of an object, with transaction time and valid time.
- **Not to be confused with:** GL-Entry.
- **Visible to:** business (shown as "version")
- **Defined normatively in:** FR-VER-011

### GL-Ontology — Ontology
- **Definition:** The shared base classes (party, role, address, money, account, calendar, document, agreement) provided by the genesis `ontology` Buk.
- **Not to be confused with:** a Buk's own model.
- **Visible to:** builder
- **Defined normatively in:** FR-MODEL-091

### GL-Outbox — Outbox
- **Definition:** The effects (events, jobs, notifications, calls) recorded with a commit and released only after it succeeds.
- **Not to be confused with:** a queue.
- **Visible to:** platform only
- **Defined normatively in:** FR-TXN-051

### GL-Overlay — Overlay
- **Definition:** A branch of kind `overlay` holding a tenant's customisation of a vendor or platform line through branch inheritance.
- **Not to be confused with:** GL-Extension.
- **Visible to:** platform only (builders see "customisation layer")
- **Defined normatively in:** FR-TEN-031

### GL-Period — Accounting Period
- **Definition:** A time range of a ledger scope with states open, closing and closed.
- **Not to be confused with:** a valid-time period of a version.
- **Visible to:** business
- **Defined normatively in:** FR-LEDG-061

### GL-Policy — Policy
- **Definition:** An authorization rule in the analysable policy language that permits or forbids actions for principals on resources.
- **Not to be confused with:** GL-GovernanceSheet.
- **Visible to:** builder
- **Defined normatively in:** FR-IAM-042

### GL-Port — Port
- **Definition:** A typed action of a class (a BPU input pin), with parameters, result, errors, availability and permission.
- **Not to be confused with:** GL-Instruction.
- **Visible to:** business (shown as "action")
- **Defined normatively in:** FR-FLOW-021

### GL-PostingGroup — Posting Group
- **Definition:** A set of double-entry ledger entries that must balance per currency.
- **Not to be confused with:** a change set.
- **Visible to:** business
- **Defined normatively in:** FR-LEDG-051

### GL-Principal — Principal
- **Definition:** An acting identity of kind human, service, agent, external or node.
- **Not to be confused with:** a party (the business entity).
- **Visible to:** builder
- **Defined normatively in:** FR-IAM-031

### GL-Process — Process
- **Definition:** The unit of work in which changes are made and committed atomically, with its initiator, trigger and lineage.
- **Not to be confused with:** GL-Workflow.
- **Visible to:** platform only
- **Defined normatively in:** FR-TXN-011

### GL-Profile — Execution Profile
- **Definition:** A named set of limits for logic execution (`strict`, `standard`, `batch`, `simulation`, `agent`).
- **Not to be confused with:** GL-ConformanceProfile.
- **Visible to:** platform only
- **Defined normatively in:** FR-LOGIC-061

### GL-Projection — Projection
- **Definition:** A declared, non-authoritative, rebuildable typed table derived from authoritative state.
- **Not to be confused with:** a class.
- **Visible to:** builder
- **Defined normatively in:** FR-ANL-011

### GL-Provenance — Provenance
- **Definition:** The recorded causes and inputs of a commit or value: trigger, process chain and dependency set.
- **Not to be confused with:** the audit trail (who changed what).
- **Visible to:** builder (shown as "lineage")
- **Defined normatively in:** FR-TXN-041

### GL-RawDocumentKind — RawDocument Kind
- **Definition:** The state kind for untyped JSON stored faithfully, validated only by envelope, and usable by typed rules only after parsing.
- **Not to be confused with:** a file.
- **Visible to:** builder
- **Defined normatively in:** FR-MODEL-055

### GL-Release — Release
- **Definition:** A signed tag with a release object (version, notes, included change sets, approvals).
- **Not to be confused with:** GL-Tag (without release metadata).
- **Visible to:** builder
- **Defined normatively in:** FR-VER-062

### GL-Relationship — Relationship
- **Definition:** A declared, typed, directed link between classes with cardinality, inverse name and ownership. It may carry attributes and valid time.
- **Not to be confused with:** GL-AuthorizationRelation.
- **Visible to:** builder
- **Defined normatively in:** FR-MODEL-061

### GL-Replay — Replay
- **Definition:** Re-execution of a recorded process from its journal, without side effects, to reproduce or compare results.
- **Not to be confused with:** event replay to subscribers.
- **Visible to:** builder
- **Defined normatively in:** FR-LOGIC-073

### GL-ReplicationScope — Replication Scope
- **Definition:** The set of objects (by class, query, classification and time window) replicated to a device or peer.
- **Not to be confused with:** a VAE.
- **Visible to:** builder
- **Defined normatively in:** FR-SYNC-021

### GL-Restatement — Restatement
- **Definition:** Recomputation and republication of derived results after a retroactive correction, keeping the original results readable.
- **Not to be confused with:** GL-Revert.
- **Visible to:** business
- **Defined normatively in:** FR-TIME-043

### GL-Retention — Retention
- **Definition:** The rules for how long records must be kept and when they may be disposed of.
- **Not to be confused with:** GL-LegalHold.
- **Visible to:** business
- **Defined normatively in:** FR-AUD-071

### GL-Retroactive — Retroactive Change
- **Definition:** A change whose valid time starts before the current business day.
- **Not to be confused with:** a future-dated change.
- **Visible to:** business (shown as "back-dated")
- **Defined normatively in:** FR-TIME-041

### GL-Reversal — Reversal
- **Definition:** A ledger entry that fully negates a referenced entry.
- **Not to be confused with:** GL-Revert (branch-level undo).
- **Visible to:** business
- **Defined normatively in:** FR-LEDG-021

### GL-Revert — Revert
- **Definition:** Undoing a commit, change set or process by a compensating commit, with ledger effects handled by reversals.
- **Not to be confused with:** GL-Reversal.
- **Visible to:** builder (business users see "undo")
- **Defined normatively in:** FR-VER-071

### GL-RuleBinding — Rule Binding
- **Definition:** The recorded versions of classes, sheets, decision tables and logic used to validate or compute a commit or result.
- **Not to be confused with:** GL-Provenance.
- **Visible to:** builder
- **Defined normatively in:** FR-TIME-061

### GL-Saga — Saga
- **Definition:** A long-running process of steps, each with its own commit and compensation, resumable after failure.
- **Not to be confused with:** GL-Workflow (which may use sagas).
- **Visible to:** platform only
- **Defined normatively in:** FR-TXN-061

### GL-Schedule — Schedule
- **Definition:** A versioned object that fires processes by cron or business-calendar rules in a time zone.
- **Not to be confused with:** a timer inside a workflow.
- **Visible to:** builder
- **Defined normatively in:** FR-EVT-041

### GL-SchemaVersion — Schema Version
- **Definition:** The version number of a class's structure, incremented on every class change.
- **Not to be confused with:** a Buk version.
- **Visible to:** platform only
- **Defined normatively in:** FR-MODEL-081

### GL-Seal — Seal
- **Definition:** A signed binding of a signature to the rendered document hash, the bound data versions and the signer's intent.
- **Not to be confused with:** a commit signature.
- **Visible to:** business
- **Defined normatively in:** FR-SIGN-021

### GL-Selector — Selector
- **Definition:** The matching expression of a governance-sheet block over classes, attributes, tags, states and context.
- **Not to be confused with:** a query.
- **Visible to:** builder
- **Defined normatively in:** FR-RULE-012

### GL-Server — Server
- **Definition:** The enterprise edition of the UBOS Node on PostgreSQL, single node or clustered.
- **Not to be confused with:** GL-Cell.
- **Visible to:** builder
- **Defined normatively in:** UBS-REQ-01

### GL-SharedBpu — Shared BPU
- **Definition:** A BPU replicated between organisations with one shared history. Definition changes require every party's signatures.
- **Not to be confused with:** a published object.
- **Visible to:** business (shown as "shared record")
- **Defined normatively in:** FR-SYNC-071

### GL-Simulation — Simulation
- **Definition:** Evaluating changed rules, logic or classes against historical or scenario data on a sandbox, without effects, to report differences.
- **Not to be confused with:** a merge preview.
- **Visible to:** builder
- **Defined normatively in:** FR-RULE-071

### GL-SmartGrid — Smart Grid
- **Definition:** A spreadsheet interface in which rows are objects and computed columns are shared logic.
- **Not to be confused with:** an imported spreadsheet file.
- **Visible to:** business
- **Defined normatively in:** FR-OFFICE-041

### GL-Specificity — Specificity
- **Definition:** The ranking of selectors by the precision of their match (class depth, attribute and context conditions), used in the cascade.
- **Not to be confused with:** priority.
- **Visible to:** builder
- **Defined normatively in:** FR-RULE-021

### GL-StateKind — State Kind
- **Definition:** The kind of a class's state: Definition, Ledger, System or RawDocument. It determines versioning and merge semantics.
- **Not to be confused with:** GL-BranchKind.
- **Visible to:** builder
- **Defined normatively in:** FR-MODEL-051

### GL-Subscription — Subscription
- **Definition:** A versioned object that routes events matching a filter to a handler.
- **Not to be confused with:** a UBTP live query subscription.
- **Visible to:** builder
- **Defined normatively in:** FR-EVT-021

### GL-SystemKind — System Kind
- **Definition:** The state kind for kernel bookkeeping objects (jobs, schedules' runtime state, sessions, cursors), written only by kernel services.
- **Not to be confused with:** GL-DefinitionKind.
- **Visible to:** platform only
- **Defined normatively in:** FR-MODEL-054

### GL-Tag — Tag
- **Definition:** An immutable, signed name for one commit.
- **Not to be confused with:** a label or keyword on an object.
- **Visible to:** builder
- **Defined normatively in:** FR-VER-061

### GL-Task — Task
- **Definition:** A human work item with subject, assignee, due time, priority and state.
- **Not to be confused with:** GL-Job.
- **Visible to:** business
- **Defined normatively in:** FR-FLOW-051

### GL-Tenant — Tenant
- **Definition:** The owning organisation (or person) of one or more VAEs, the unit of ownership, isolation and billing.
- **Not to be confused with:** GL-Vae.
- **Visible to:** builder
- **Defined normatively in:** FR-TEN-011

### GL-Tombstone — Tombstone
- **Definition:** A marker on a child branch that hides an inherited object without deleting it on the parent.
- **Not to be confused with:** disposal.
- **Visible to:** platform only
- **Defined normatively in:** FR-VER-083

### GL-Tool — Tool
- **Definition:** A typed, permission-filtered operation (from ports and saved queries) that agents and AI clients can call.
- **Not to be confused with:** GL-Instruction.
- **Visible to:** builder
- **Defined normatively in:** FR-AI-041

### GL-Trait — Trait
- **Definition:** A reusable, named group of fields, ports and rules that a class includes in addition to its single parent, ordered by C3 linearization.
- **Not to be confused with:** GL-Class (a trait cannot be instantiated).
- **Visible to:** builder
- **Defined normatively in:** FR-MODEL-022

### GL-TransactionTime — Transaction Time
- **Definition:** The kernel-assigned time at which a fact was recorded (commit time).
- **Not to be confused with:** GL-ValidTime.
- **Visible to:** business (shown as "recorded on" or "as known on")
- **Defined normatively in:** FR-TIME-011

### GL-TrustRelationship — Trust Relationship
- **Definition:** A mutually approved object that defines the allowed interactions and data classifications between two organisations' VAEs.
- **Not to be confused with:** a contract BPU.
- **Visible to:** builder
- **Defined normatively in:** FR-SYNC-053

### GL-Ubtp — UBTP
- **Definition:** The UBOS client–server protocol (Handshake, Mutate, Query, Subscribe, Emit, Sync) with TCP, WebSocket, HTTP, in-process and QUIC bindings.
- **Not to be confused with:** GL-Abi.
- **Visible to:** platform only
- **Defined normatively in:** FR-INT-011

### GL-UnitOfWork — Unit of Work
- **Definition:** The private buffer of changes of a running process, invisible to others until flush.
- **Not to be confused with:** GL-ChangeSet.
- **Visible to:** platform only
- **Defined normatively in:** FR-TXN-012

### GL-Uri — Canonical URI
- **Definition:** The address of an object, `ubos://<tenant>[.<vae>]/<Class>/<slug>`, with optional selectors (`branch`, `commit`, `tag`, `time`, `asof`).
- **Not to be confused with:** GL-Vfs paths.
- **Visible to:** platform only
- **Defined normatively in:** FR-VER-104

### GL-Vae — VAE (Virtual Application Environment)
- **Definition:** A complete logical world of a tenant, with its own branches, installed Buks, role assignments and configuration.
- **Not to be confused with:** GL-Tenant.
- **Visible to:** builder (business users see "workspace" or "company")
- **Defined normatively in:** FR-TEN-012

### GL-VaeTree — VAE Tree
- **Definition:** A hierarchy of parent and child VAEs, on one node or across nodes, with logic inherited downward and data kept local.
- **Not to be confused with:** GL-BranchInheritance (the mechanism it uses).
- **Visible to:** builder
- **Defined normatively in:** FR-TEN-041

### GL-ValidTime — Valid Time
- **Definition:** The business period during which a fact is true.
- **Not to be confused with:** GL-TransactionTime.
- **Visible to:** business (shown as "effective")
- **Defined normatively in:** FR-TIME-021

### GL-ValueType — Value Type
- **Definition:** A standard or custom type of field values, with a canonical JSON representation.
- **Not to be confused with:** GL-Class.
- **Visible to:** builder
- **Defined normatively in:** FR-MODEL-041

### GL-Verifier — Verifier
- **Definition:** The open tool and library that verifies signatures, hashes, proofs, anchors, seals and evidence packs without vendor services.
- **Not to be confused with:** Buk verification.
- **Visible to:** business
- **Defined normatively in:** FR-PROOF-061

### GL-Vfs — VFS (Virtual File System view)
- **Definition:** Human-readable path aliases (`/data`, `/usr`, `/etc`, `/view`, `/lib`) that resolve to canonical URIs.
- **Not to be confused with:** GL-Uri.
- **Visible to:** builder
- **Defined normatively in:** FR-FILE-041

### GL-ViewObject — View Object
- **Definition:** A versioned description of a user interface (layouts, sections, widgets and bindings) rendered by clients.
- **Not to be confused with:** GL-Projection.
- **Visible to:** builder
- **Defined normatively in:** FR-UX-011

### GL-WarRoom — War Room
- **Definition:** A live, drillable, actionable presentation deck bound to dashboards and records.
- **Not to be confused with:** a static slide file.
- **Visible to:** business
- **Defined normatively in:** FR-OFFICE-051

### GL-Watermark — Watermark
- **Definition:** The last commit reflected in an asynchronous projection, index or export.
- **Not to be confused with:** a Merkle root.
- **Visible to:** builder
- **Defined normatively in:** FR-LEDG-033

### GL-Widget — Widget
- **Definition:** A user-interface component from the versioned widget catalogue that all clients implement.
- **Not to be confused with:** GL-ViewObject.
- **Visible to:** builder
- **Defined normatively in:** FR-UX-014

### GL-Worker — Worker
- **Definition:** An organisation-owned machine registered to execute verified, sandboxed jobs without authoritative state (DEC-002).
- **Not to be confused with:** an application node.
- **Visible to:** platform only
- **Defined normatively in:** FR-EVT-061

### GL-Workflow — Workflow
- **Definition:** A versioned, durable definition of multi-step work across time, objects and people.
- **Not to be confused with:** GL-Lifecycle.
- **Visible to:** builder
- **Defined normatively in:** FR-FLOW-061

### GL-Worm — WORM (Write Once, Read Many)
- **Definition:** Storage mode in which records cannot be rewritten or erased until their retention ends.
- **Not to be confused with:** immutability of commits (which is logical).
- **Visible to:** builder
- **Defined normatively in:** FR-AUD-073

### GL-WritePolicy — Write Policy
- **Definition:** The per-class rule for protected branches: `direct` (operational commits) or `change_set` (reviewed changes only).
- **Not to be confused with:** a permission.
- **Visible to:** builder
- **Defined normatively in:** FR-VER-024
