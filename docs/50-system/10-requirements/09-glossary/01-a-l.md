# Glossary — A to L

### GL-Abi — ABI (Instruction ABI)
- **Definition:** The versioned application binary interface of the instruction set. It covers instruction names, parameters, results, errors and determinism classes. Minor versions only add.
- **Not to be confused with:** GL-Ubtp (the client protocol).
- **Visible to:** platform only
- **Defined normatively in:** FR-LOGIC-012

### GL-ActionMessage — Action Message
- **Definition:** A message (in-app, e-mail or chat) that carries a governed, version-bound, single-use action on a BPU.
- **Not to be confused with:** a plain notification.
- **Visible to:** business
- **Defined normatively in:** FR-OFFICE-061

### GL-Adjustment — Adjustment
- **Definition:** A ledger entry that corrects one or more earlier entries by a stated amount, referencing them.
- **Not to be confused with:** GL-Reversal (which negates an entry fully).
- **Visible to:** business
- **Defined normatively in:** FR-LEDG-022

### GL-AgentBranch — Agent Branch
- **Definition:** A branch of kind `agent` on which a single agent run works. Its results reach protected branches only through a reviewed change set.
- **Not to be confused with:** GL-Overlay.
- **Visible to:** builder (shown to supervisors as "agent proposal")
- **Defined normatively in:** FR-AI-031

### GL-AiBuilder — AI Builder
- **Definition:** The Agent Hub function that generates Buk drafts from natural-language requirements.
- **Not to be confused with:** GL-Copilot.
- **Visible to:** builder
- **Defined normatively in:** FR-AI-071

### GL-Anchor — Anchor
- **Definition:** A record that a tenant Merkle root existed at a time, obtained from an external timestamping service.
- **Not to be confused with:** a blockchain transaction as a system of record.
- **Visible to:** builder
- **Defined normatively in:** FR-PROOF-041

### GL-Approval — Approval
- **Definition:** A recorded decision by an eligible principal on a pending change, with evidence of what was approved.
- **Not to be confused with:** GL-Decision (an automatic policy result).
- **Visible to:** business
- **Defined normatively in:** FR-FLOW-044

### GL-Asof — As-of (valid-time selector)
- **Definition:** The valid-time point at which a read or query is evaluated. Its companion `time` selects transaction time.
- **Not to be confused with:** GL-TransactionTime.
- **Visible to:** business (shown as "as of")
- **Defined normatively in:** FR-TIME-031

### GL-AuthorizationRelation — Authorization Relation
- **Definition:** A named relation derived from the model (for example `owner` or `manager_of`) that policies use to grant permissions.
- **Not to be confused with:** GL-Relationship (the business link it is derived from).
- **Visible to:** builder
- **Defined normatively in:** FR-IAM-051

### GL-Bitemporal — Bitemporal
- **Definition:** Having both transaction time and valid time, so that the state as known at any time about any time can be queried.
- **Not to be confused with:** plain versioning.
- **Visible to:** builder
- **Defined normatively in:** CAP-TIME-03

### GL-Box — Box
- **Definition:** The personal and desktop edition of the UBOS Node, with local SQLite storage and offline operation.
- **Not to be confused with:** GL-BrowserKernel.
- **Visible to:** business
- **Defined normatively in:** UBS-REQ-01

### GL-Bpa — BPA (Business Processing Architecture)
- **Definition:** The public, language-neutral standard that defines the DVM semantics, the BPU, the instruction set, the governance-sheet language, addressing, protocols, error codes and conformance.
- **Not to be confused with:** GL-Dvm (its reference implementation).
- **Visible to:** platform only
- **Defined normatively in:** UBS-META-00

### GL-Bpu — BPU (Business Processing Unit)
- **Definition:** The standard business unit. Each business thing (a contract, order or policy) is a BPU instance defined by seven elements (GL-BpuElement).
- **Not to be confused with:** GL-Object (the storage-level concept).
- **Visible to:** builder
- **Defined normatively in:** UBS-META-06

### GL-BpuElement — BPU Element
- **Definition:** One of the seven elements of a BPU:
  1. class;
  2. state (Definition and Ledger);
  3. lifecycle (clock);
  4. ports;
  5. governance binding;
  6. knowledge;
  7. proof.
- **Not to be confused with:** GL-Field.
- **Visible to:** builder
- **Defined normatively in:** UBS-META-06

### GL-Branch — Branch
- **Definition:** A named, zero-copy line of commits within a VAE.
- **Not to be confused with:** GL-ChangeSet (the business-facing unit of review).
- **Visible to:** platform only (business users see "draft")
- **Defined normatively in:** FR-VER-021

### GL-BranchInheritance — Branch Inheritance
- **Definition:** Read-through resolution from a child branch to its parent line for objects that the child does not hold locally.
- **Not to be confused with:** GL-Linearization (class inheritance).
- **Visible to:** platform only
- **Defined normatively in:** FR-VER-081

### GL-BranchKind — Branch Kind
- **Definition:** The declared purpose of a branch: `main`, `release`, `draft`, `feature`, `agent`, `overlay`, `loader`, `evolution`, `correction` or `sandbox`. Each kind has its own policies.
- **Not to be confused with:** GL-StateKind.
- **Visible to:** platform only
- **Defined normatively in:** FR-VER-022

### GL-BrowserKernel — Browser Kernel
- **Definition:** The DVM compiled to WebAssembly and running in a browser with local storage.
- **Not to be confused with:** GL-Box.
- **Visible to:** platform only
- **Defined normatively in:** FR-SYNC-081

### GL-Buk — Buk
- **Definition:** A signed, versioned package of classes, rules, logic, views, knowledge, seed data and scenarios. It is the unit of feature delivery.
- **Not to be confused with:** GL-ExecutableBook (one kind of Buk content).
- **Visible to:** builder
- **Defined normatively in:** FR-PKG-011

### GL-Cascade — Cascade
- **Definition:** The deterministic resolution of competing governance-sheet declarations by layer, specificity, priority and order.
- **Not to be confused with:** GL-Linearization.
- **Visible to:** builder
- **Defined normatively in:** FR-RULE-021

### GL-Cell — Cell
- **Definition:** A self-contained hosted deployment unit (application nodes plus storage) that serves many tenants. Tenants can move between cells.
- **Not to be confused with:** GL-Vae.
- **Visible to:** platform only
- **Defined normatively in:** FR-TEN-071

### GL-Certification — Certification ("BPU Compliant")
- **Definition:** Formal recognition that an implementation passes the conformance vectors of one or more conformance profiles.
- **Not to be confused with:** Buk verification.
- **Visible to:** platform only
- **Defined normatively in:** FR-STD-051

### GL-ChangeSet — Change Set
- **Definition:** The reviewable unit of governed change from a source branch to a target branch, with lifecycle, approvals and simulations.
- **Not to be confused with:** GL-Commit.
- **Visible to:** builder (business users see "change" or "draft")
- **Defined normatively in:** FR-VER-031

### GL-Class — Class
- **Definition:** A versioned definition of a kind of object: fields, kind, parent, traits, ports, lifecycle, views and knowledge.
- **Not to be confused with:** GL-ValueType.
- **Visible to:** builder
- **Defined normatively in:** FR-MODEL-011

### GL-Classification — Classification
- **Definition:** The data sensitivity of a field: `public`, `internal`, `confidential`, `personal` or `sensitive_personal`.
- **Not to be confused with:** a tag.
- **Visible to:** builder
- **Defined normatively in:** FR-MODEL-047

### GL-Commit — Commit
- **Definition:** The immutable, signed record of a set of changes on one branch, with parents, author, process, transaction time and Merkle root. One commit is one "clock cycle" of the DVM.
- **Not to be confused with:** GL-ChangeSet.
- **Visible to:** platform only (business users see "saved version")
- **Defined normatively in:** FR-VER-011

### GL-Conflict — Conflict
- **Definition:** A field changed differently on both sides of a merge relative to the merge base.
- **Not to be confused with:** a validation failure.
- **Visible to:** builder
- **Defined normatively in:** FR-VER-052

### GL-ConformanceProfile — Conformance Profile
- **Definition:** A named subset of the BPA (for example Core, Bitemporal, Ledger, Governance, Proof, Sync, Browser) that an implementation can claim.
- **Not to be confused with:** GL-Profile (execution profile).
- **Visible to:** platform only
- **Defined normatively in:** FR-STD-014

### GL-ConformanceVector — Conformance Vector
- **Definition:** A language-neutral test case of inputs, operations and expected outputs or errors for a standard clause.
- **Not to be confused with:** a scenario.
- **Visible to:** platform only
- **Defined normatively in:** FR-STD-021

### GL-Connector — Connector
- **Definition:** A governed object that declares how logic may call one external system, with credentials held by the platform.
- **Not to be confused with:** a webhook.
- **Visible to:** builder
- **Defined normatively in:** FR-LOGIC-101

### GL-ConsistencyProof — Consistency Proof
- **Definition:** A proof that a later commit extends an earlier one on a branch's history without rewriting.
- **Not to be confused with:** GL-InclusionProof.
- **Visible to:** platform only
- **Defined normatively in:** FR-PROOF-033

### GL-ContentAddress — Content Address
- **Definition:** The identifier of content derived from the hash of its canonical form.
- **Not to be confused with:** a UUID.
- **Visible to:** platform only
- **Defined normatively in:** FR-PROOF-012

### GL-Context — Context (`ctx`)
- **Definition:** The immutable input of an execution: identity, tenant, VAE, branch, times, locale, process, trigger, input, profile and budget.
- **Not to be confused with:** GL-Gateway.
- **Visible to:** platform only
- **Defined normatively in:** FR-LOGIC-021

### GL-ControlPlane — Control Plane
- **Definition:** The system that manages nodes, cells, tenants, licences, upgrades and metering, without access to business data.
- **Not to be confused with:** GL-Server.
- **Visible to:** platform only
- **Defined normatively in:** FR-OPS-081

### GL-Copilot — Copilot
- **Definition:** The in-context assistant in Workspace. It answers, explains and proposes drafts, and never commits silently.
- **Not to be confused with:** an agent that runs autonomously.
- **Visible to:** business
- **Defined normatively in:** FR-AI-061

### GL-CryptoShredding — Crypto-shredding
- **Definition:** Erasure of personal data by destroying the per-subject keys that encrypt it, leaving hashes and proofs intact.
- **Not to be confused with:** deletion of history.
- **Visible to:** builder
- **Defined normatively in:** FR-PROOF-073

### GL-Decision — Decision
- **Definition:** A policy evaluation before an action, returning allow, deny or require (additional steps). Deny overrides.
- **Not to be confused with:** GL-Approval.
- **Visible to:** builder
- **Defined normatively in:** FR-RULE-051

### GL-Declaration — Declaration
- **Definition:** A property–value pair in a governance-sheet block that sets a governed property on matched objects.
- **Not to be confused with:** a field value.
- **Visible to:** builder
- **Defined normatively in:** FR-RULE-013

### GL-DeferredCommit — Deferred Commit
- **Definition:** A pending change held until its approvals are complete, then applied atomically.
- **Not to be confused with:** a draft branch.
- **Visible to:** platform only (business users see "awaiting approval")
- **Defined normatively in:** FR-FLOW-042

### GL-DefinitionKind — Definition Kind
- **Definition:** The state kind for configuration, master data, rules, documents and other state that is branched, merged and effective-dated.
- **Not to be confused with:** GL-LedgerKind.
- **Visible to:** builder
- **Defined normatively in:** FR-MODEL-052

### GL-Delegation — Delegation
- **Definition:** A time-bound, scoped transfer of task or approval authority from one principal to another, within policy.
- **Not to be confused with:** role assignment.
- **Visible to:** business
- **Defined normatively in:** FR-FLOW-091

### GL-Did — DID (Decentralised Identifier)
- **Definition:** The identifier of a principal (`did:ubos:…`) bound to its verification keys.
- **Not to be confused with:** a user name.
- **Visible to:** platform only
- **Defined normatively in:** FR-IAM-032

### GL-Diff — Diff
- **Definition:** The object- and field-level difference between two states.
- **Not to be confused with:** GL-Conflict.
- **Visible to:** business (shown as "changes")
- **Defined normatively in:** FR-VER-041

### GL-Dvm — DVM (Data Virtual Machine)
- **Definition:** The reference engine implementing the BPA: typed, inheritable, polymorphic, versioned, bitemporal and provable business state, plus a sandboxed deterministic logic runtime.
- **Not to be confused with:** a database.
- **Visible to:** platform only
- **Defined normatively in:** UBS-META-00

### GL-Entry — Entry
- **Definition:** An immutable record of a Ledger-kind class, with a sequence number, transaction time and valid time.
- **Not to be confused with:** GL-ObjectVersion.
- **Visible to:** business
- **Defined normatively in:** FR-MODEL-053

### GL-Event — Event
- **Definition:** A typed notification that something happened, emitted after commit and representable as a CloudEvent.
- **Not to be confused with:** GL-Entry.
- **Visible to:** builder
- **Defined normatively in:** FR-EVT-011

### GL-EvidencePack — Evidence Pack
- **Definition:** A self-contained, verifiable archive of records, versions, rules, signatures, proofs and anchors for a scoped question.
- **Not to be confused with:** an export.
- **Visible to:** business
- **Defined normatively in:** FR-PROOF-051

### GL-EvolutionProposal — Evolution Proposal
- **Definition:** A change set on an `evolution` branch proposing class, rule or view changes, generated from observed patterns and merged only by authorised people.
- **Not to be confused with:** an agent change set for data.
- **Visible to:** builder
- **Defined normatively in:** FR-AI-102

### GL-ExecutableBook — Executable Book
- **Definition:** A readable and runnable document that mixes narrative, logic blocks and views, shipped as a Buk.
- **Not to be confused with:** GL-LiveDoc.
- **Visible to:** business
- **Defined normatively in:** FR-OFFICE-071

### GL-Extension — Extension
- **Definition:** A declaration by a tenant or Buk that adds members to a class it does not own, under the narrowing rule.
- **Not to be confused with:** a subclass.
- **Visible to:** builder
- **Defined normatively in:** FR-MODEL-071

### GL-Federation — Federation
- **Definition:** The network of independent VAEs on different nodes that interact through trust relationships, without central control of data.
- **Not to be confused with:** GL-Cell.
- **Visible to:** builder
- **Defined normatively in:** CAP-SYNC-05

### GL-Field — Field
- **Definition:** A typed member of a class, with constraints, classification and documentation.
- **Not to be confused with:** GL-Declaration.
- **Visible to:** business
- **Defined normatively in:** FR-MODEL-012

### GL-Flush — Flush
- **Definition:** The single storage transaction that writes a process's unit of work and commit records.
- **Not to be confused with:** GL-Commit (the resulting record).
- **Visible to:** platform only
- **Defined normatively in:** FR-TXN-012

### GL-Gateway — Gateway (`sys`)
- **Definition:** The least-privilege capability object through which logic issues instructions.
- **Not to be confused with:** GL-ModelGateway.
- **Visible to:** platform only
- **Defined normatively in:** FR-LOGIC-023

### GL-Genesis — Genesis
- **Definition:** The bootstrap of a VAE by installing the embedded `system` and `ontology` Buks.
- **Not to be confused with:** a Buk upgrade.
- **Visible to:** platform only
- **Defined normatively in:** FR-PKG-071

### GL-GovernanceSheet — Governance Sheet (LGS)
- **Definition:** A versioned object of rule blocks (selector plus declarations) applied to objects in a cascade, like CSS for business rules.
- **Not to be confused with:** GL-Policy (authorization).
- **Visible to:** builder (shown as "rule sheet")
- **Defined normatively in:** FR-RULE-011

### GL-Guard — Guard
- **Definition:** A precondition on an action or transition that returns pass or fail with an explanation.
- **Not to be confused with:** a validation.
- **Visible to:** builder
- **Defined normatively in:** FR-FLOW-031

### GL-HardenedMechanism — Hardened Mechanism
- **Definition:** The principle that state-change mechanics are standardised, deterministic and verifiable like hardware, while business policy stays soft and versioned.
- **Not to be confused with:** hard-coded business rules.
- **Visible to:** platform only
- **Defined normatively in:** UBS-META-06

### GL-Idempotency — Idempotency
- **Definition:** The property that repeating a request with the same key has exactly one effect.
- **Not to be confused with:** determinism.
- **Visible to:** platform only
- **Defined normatively in:** FR-TXN-031

### GL-ImmuneSystem — Immune System
- **Definition:** The combination of static analysis (innate) and runtime limits, circuit breakers and quarantine (adaptive) that protects the node from logic.
- **Not to be confused with:** antivirus scanning of files.
- **Visible to:** platform only
- **Defined normatively in:** FR-LOGIC-091

### GL-InclusionProof — Inclusion Proof
- **Definition:** A logarithmic-size proof that an object version is part of a Merkle root.
- **Not to be confused with:** GL-ConsistencyProof.
- **Visible to:** platform only
- **Defined normatively in:** FR-PROOF-032

### GL-Instruction — Instruction
- **Definition:** A single operation of the ABI, the only way for logic to affect or observe state and the outside world.
- **Not to be confused with:** a port.
- **Visible to:** platform only
- **Defined normatively in:** FR-LOGIC-011

### GL-InstructionFamily — Instruction Family
- **Definition:** One of the seven groups of instructions: `commit`, `read`, `run`, `emit`, `search`, `call` and `ask`.
- **Not to be confused with:** a profile.
- **Visible to:** platform only
- **Defined normatively in:** FR-LOGIC-011

### GL-Job — Job
- **Definition:** A durable System-kind object that represents asynchronous work with state, attempts and a lease.
- **Not to be confused with:** a queue message.
- **Visible to:** builder
- **Defined normatively in:** FR-EVT-031

### GL-Journal — Execution Journal
- **Definition:** The record of a process's logic versions, inputs, snapshots, non-deterministic values, external exchanges and outputs.
- **Not to be confused with:** the audit log.
- **Visible to:** platform only
- **Defined normatively in:** FR-LOGIC-072

### GL-Knowledge — Knowledge
- **Definition:** The BPU element holding explanations, procedures, policies, examples and references attached to a class, retrievable by users and agents.
- **Not to be confused with:** a field description.
- **Visible to:** business
- **Defined normatively in:** FR-AI-051

### GL-LedgerKind — Ledger Kind
- **Definition:** The state kind for append-only facts corrected only by reversal or adjustment and never merged.
- **Not to be confused with:** GL-DefinitionKind.
- **Visible to:** builder
- **Defined normatively in:** FR-MODEL-053

### GL-LegalHold — Legal Hold
- **Definition:** A scoped preservation order that suspends disposal and erasure.
- **Not to be confused with:** GL-Retention.
- **Visible to:** business
- **Defined normatively in:** FR-AUD-061

### GL-Lens — Lens
- **Definition:** A declarative, preferably bidirectional mapping between two schema versions of a class.
- **Not to be confused with:** a migration process.
- **Visible to:** builder
- **Defined normatively in:** FR-MODEL-082

### GL-Lifecycle — Lifecycle
- **Definition:** A class's state machine: states, transitions, guards and effects. It is the BPU "clock".
- **Not to be confused with:** GL-Workflow.
- **Visible to:** builder
- **Defined normatively in:** FR-FLOW-011

### GL-Linearization — Linearization
- **Definition:** The deterministic order of a class's ancestors and traits, computed by C3, used for resolution and polymorphism.
- **Not to be confused with:** GL-BranchInheritance.
- **Visible to:** platform only
- **Defined normatively in:** FR-MODEL-022

### GL-LiveDoc — Live Doc
- **Definition:** A document that is a view bound to live, versioned data and embedded logic.
- **Not to be confused with:** a static file.
- **Visible to:** business
- **Defined normatively in:** FR-OFFICE-011

### GL-LoaderBranch — Loader Branch
- **Definition:** A branch of kind `loader` on which a Buk is staged and checked before its governed merge.
- **Not to be confused with:** GL-Overlay.
- **Visible to:** platform only
- **Defined normatively in:** FR-PKG-031

### GL-LogicAsset — Logic Asset
- **Definition:** A versioned object containing L2 or L3 logic, with declared types, capabilities, tests and lifecycle state.
- **Not to be confused with:** a governance sheet.
- **Visible to:** builder
- **Defined normatively in:** FR-LOGIC-041

### GL-LogicTier — Logic Tier
- **Definition:** One of three ways to express logic:
  - L1: declarative expressions, decision tables and sheets;
  - L2: typed Rhai scripts;
  - L3: WASM components.
- **Not to be confused with:** GL-Profile.
- **Visible to:** builder
- **Defined normatively in:** IMP-05
